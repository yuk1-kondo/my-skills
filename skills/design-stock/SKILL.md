# design-stock — デザインストックの利用と登録

ストックの置き場所: `~/workspace/design-stock/`（Muse の VM）。他マシン/他エージェントから使う場合は、このスキルに同梱の `STOCK_INDEX.md`（目録の同期版スナップショット）を参照するか、ユーザー（または Muse）に最新の目録と素材を確認する。素材ファイル自体は Muse の VM にあるため、実装前に素材の取得方法をユーザーに確認すること。

## 構成

- `INDEX.md` — 全エントリの目録（slug / 内容 / タグ / 出典）。まずこれを読む。
- `stock/<slug>/ENTRY.md` — エントリの詳細（パターン目録、素材ファイル名、使い方メモ）。
- `stock/<slug>/` 内の素材 — 参照動画（mp4）、静止画、フェーズ一覧画像。

## 開発時に引っ張り出す手順

1. `INDEX.md` を読み、作ろうとしている UI の要素（ボタン、トグル、進捗、遷移…）とタグが近いエントリを選ぶ。
2. そのエントリの `ENTRY.md` を読み、パターンを1〜3個に絞る。迷ったら候補をユーザーに盤面画像つきで提示する。
3. **動画のままでは実装しない。** 選んだパターンを数値レシピ（SPEC）に落とす:
   - ボード型エントリは ffmpeg で該当セルだけを crop し、高 fps でフレーム抽出して動きを計測する。
   - SPEC の項目: 状態の遷移順、各ステップの duration（ms）、easing（cubic-bezier か spring のパラメータ）、transform/opacity の始点→終点、ループの有無と間隔。
   - 計測できない部分は「目安」と明記して標準値で補う（例: easeOut cubic-bezier(0.22, 1, 0.36, 1)、press の scale 0.92〜0.97）。
4. SPEC をエントリフォルダに `SPEC-<pattern>.md` として保存してから実装する（次回から再利用できるように）。
5. 実装はプロジェクト側の流儀（CSS / GSAP / Framer Motion / Remotion 等）に合わせて行う。ストック側にコードは置かない（レシピまで）。

## 新しくストックする手順（ユーザーがリンク/画像を共有したら）

1. 素材を取得する（動画は mp4 で保存、画像はそのまま）。X の動画は FxTwitter API 経由で動画 URL を得られることが多い。
2. 動画は ffmpeg で静止画とフェーズ一覧を作り、中身を確認してから目録化する（見ずに登録しない）。
3. `stock/<slug>/ENTRY.md` を書く: 種別、出典 URL、作者、日付、パターン/要素の目録（名前・概要・タグ）、使い方メモ。
4. `INDEX.md` に1行追加する。
5. 登録したらユーザーに「何をどういうタグで入れたか」を短く報告する。

## 原則

- ストックは「完成コード集」ではなく「動きのレシピ源」。数値化されていない参考は実装に使えない、がこの仕組みの前提。
- 著作権のある素材は個人の参考・学習用として扱い、素材そのものを成果物にそのまま同梱しない（動きの再実装は可）。
- 出典（URL・作者）は必ず ENTRY.md に残す。
